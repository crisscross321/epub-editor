# 手机 EPUB 编辑器 — 设计说明

日期：2026-08-15  
状态：待实现  
仓库：`/Users/crissxu/vibecoding/epub-editor`

## 1. 目标

做一个能在手机上用的 EPUB 编辑器。第一版给自己用：可以新建一本书，也可以打开已有 `.epub`，改完导出 EPUB 3。

先做成 Capacitor 工程（网页 + Android）。日常用浏览器预览界面；打开本地文件、另存为、打 APK 走 Android。

## 2. 已确认的决定

| 项 | 决定 |
|---|---|
| 形态 | 方案 2：第一天就是 Capacitor 工程，不是「网页做完再套壳」 |
| 能力 | 新建 + 打开已有 EPUB，编辑后导出 |
| 打开已有书 | 按章节处理：正在改的章节简化编辑；没打开过的章节按原文件字节打回包 |
| 打开章节 | 先提示「该章会简化排版」，确认后才转换 |
| 存储 | 应用内书架自动保存 + 可打开/另存为到系统目录 |
| 丢失 | 卸载 App 或清除站点数据后，书架可以丢；另存为才是备份 |
| 图片 | 相册或本地文件，不调用摄像头 |
| 图片体积 | 插入时自动压缩，单张目标不超过约 2MB |
| 格式 | 多级标题、正文、粗体/斜体、有序/无序列表、图片、撤销重做、全选/复制/粘贴 |
| 书籍结构 | 可新增、删除、重排章节；可改书名、作者、语言、封面 |
| 加密书 | 不支持，提示无法打开 |
| 导出 | 只导出 EPUB 3 |
| 界面 | 中文；手机优先，电脑浏览器也能用 |
| 预览 | 编辑页接近成书效果，另有阅读预览 |
| 定位 | 个人工具，不为第一版做完整产品化文案体系 |

## 3. 明确不做（第一版）

- 表格、脚注、公式、链接、引用块、段首缩进、文字颜色、对齐、字号
- 摄像头拍照
- DRM / 加密 EPUB
- EPUB 2 导出（打开 EPUB 2 可以，导出统一成 EPUB 3）
- 中英切换、云同步、多人协作、自动备份到「下载」
- 自定义 CSS、音频视频、复杂版式保真编辑

## 4. 用户流程

### 4.1 书架

- 看到应用内已有的书（书名、作者、最近修改时间）。
- 「新建书籍」：生成一本只有一章空白正文的书，进入章节列表。默认书名为「未命名」，作者空，语言 `zh-CN`。
- 「打开 EPUB」：系统文件选择器选 `.epub`，复制成应用内工作副本后出现在书架。
- 点一本书：进入该书的章节列表。
- 删除：只删应用内副本，不动系统目录里另存过的文件。

### 4.2 章节列表

- 按 spine 顺序列出章节标题。
- 点某一章：
  - 若该章已是简化稿：直接进入编辑。
  - 若该章仍是原文件：先弹窗说明「进入编辑后，这一章的原始排版无法完整保留」。取消则留在列表；确认则转换并进入编辑。
- 可新增章节、删除章节、拖动排序。
- 入口：书籍信息（书名/作者/语言/封面）、阅读预览、导出/另存为。

### 4.3 编辑一章

- 所见即所得，样式接近阅读时的重排正文（衬线或接近电子书的默认字体、合适行距、图片宽度不超过屏宽）。
- 工具栏贴在编辑区顶部；弹出键盘时编辑区上移，工具栏不被挡住。手机上按钮足够大，避免误触。
- 可设 H1–H6、正文、粗体、斜体、有序/无序列表、插入图片、撤销、重做。
- 系统提供的全选、复制、粘贴照常可用。
- 修改后短延迟自动写入应用内存储，不设「保存章节」按钮。

### 4.4 阅读预览

- 按当前书籍（含已简化章节 + 未打开章节的可解析正文）顺序浏览。
- 未打开章节尽量用原 HTML 只读渲染；渲染失败则显示「本章尚未编辑，预览可能不完整」并给出纯文本回退。
- 预览不可编辑。

### 4.5 导出 / 另存为

- 生成合法 EPUB 3，让用户选系统目录保存（如下载、文档）。
- 导出失败时不留下半成品包，用中文说明原因。

## 5. 架构

三层，全部跑在客户端，无后端。

```
界面（React）
  书架 / 章节列表 / 编辑器 / 书籍信息 / 阅读预览
        ↓
书籍服务
  新建、导入、自动保存、删书、导出
        ↓
EPUB 引擎 + 存储
  解包 / 按章转换 / 原样回写 / 打包 EPUB 3
  Capacitor Filesystem（App 私有目录 + 另存为）
```

- **界面**：Vite + React + TypeScript。编辑器用 TipTap（ProseMirror）。
- **EPUB 引擎**：JSZip 处理 zip；自行解析 `container.xml`、OPF、spine、nav/NCX；自行写出 EPUB 3。
- **存储**：Capacitor Filesystem。Android 上书架在应用私有目录；浏览器预览时插件回退到 IndexedDB，行为与「应用内可丢」一致。
- **原生插件（第一版）**：Filesystem、文件选择、Status Bar。不加入 Camera。

浏览器里 `npm run dev` 用于看界面和编辑逻辑。打开真实文件、另存为、真机键盘与安全区，用 Android 调试。

## 6. 数据模型

每本书在应用私有目录下有独立文件夹 `books/{bookId}/`。

```
books/{bookId}/
  book.json              # 元数据与章节索引
  original-entries/      # 导入时每个 zip 内路径对应的原文件字节（新建书可为空）
  chapters/{chapterId}.json   # 已简化章节的编辑器文档
  images/{imageId}       # 已简化章节用到的图（压缩后）
  cover.{ext}            # 当前封面（若有）
```

`book.json` 字段：

- `id`、`title`、`author`、`language`、`updatedAt`
- `coverPath`：可选
- `sourceName`：导入时的原文件名，可选
- `chapters[]`：
  - `id`：稳定 ID（导入时用 manifest id；新建时生成）
  - `href`：包内路径，如 `OEBPS/text/chap-2.xhtml`
  - `title`：目录显示名
  - `spineIndex`：顺序
  - `state`：`pristine`（从未确认编辑，导出时用 `original-entries` 原字节）或 `simplified`（用编辑器文档生成 XHTML）

导入时：解开 EPUB，把每个条目写入 `original-entries/`，按 spine 生成 `chapters`，全部为 `pristine`。封面、书名、作者从 OPF 读取。

新建时：不依赖原包，生成最小 EPUB 3 骨架所需的逻辑结构，第一章为 `simplified` 空文档。

## 7. EPUB 处理规则

### 7.1 打开

1. 文件必须是 zip。`mimetype` 应为 `application/epub+zip`；缺失不阻断，继续解析。无法解析 OPF 则失败。
2. 存在 `META-INF/encryption.xml` 则拒绝，提示「不支持加密的 EPUB」。
3. 读 `META-INF/container.xml` 找到 OPF。
4. 读 metadata、manifest、spine。章节 = spine 里未标 `linear="no"` 的文档项。
5. 章节标题优先 nav 文档，其次 NCX，再次文件内第一个标题，否则「第 N 章」。
6. 缺 OPF、spine 为空、zip 损坏：失败并中文说明，不写入书架。

### 7.2 原文件 → 简化文档（仅在用户确认编辑某章后）

保留并映射到编辑器：

- `h1`–`h6` → 对应标题
- `p`、`div` 中的文本 → 段落（多余包裹拆平）
- `strong`/`b`、`em`/`i` → 粗体、斜体
- `ul`/`ol`/`li` → 列表
- `img` → 图片：按章节 `href` 解析相对路径，从 `original-entries` 取文件，复制到 `images/`，必要时压缩

丢弃或降级：

- `script`、事件属性、外部样式表引用：丢掉
- `table`：每个单元格文本按段落保留，表结构不保留
- `a`：只留链接文字，不保留 URL（第一版无链接）
- `svg`、音视频：去掉，不占位
- 其他未知标签：拆开保留内部文本

转换后该章 `state = simplified`。即使用户立刻退出、几乎没改字，导出也已用简化 XHTML，不再写回原字节。这是有意为之，与确认弹窗一致。

### 7.3 导出

- 未改过结构、元数据、封面，且没有任何 `simplified` 章节：在原条目基础上只确保 EPUB 3 必要文件合法即可；所有 `pristine` 章节文件字节与导入时相同。
- 有 `simplified` 章节：用编辑器文档生成 XHTML，覆盖对应 `href`；该路径的原字节不再写入。
- 新增章节：写新的 XHTML，加入 manifest 与 spine，并更新 `nav.xhtml`。
- 删除章节：从 spine、manifest、nav 移除；该文件不再打进包。
- 重排：只改 spine 与 nav 顺序；`pristine` 文件内容不变。
- 书名/作者/语言/封面：写进 OPF；封面图写入包内并声明 `properties="cover-image"`。
- 包结构：`mimetype` 为 zip 首个条目且不压缩；其余按 EPUB 3。
- 输出文件扩展名 `.epub`。

**验收硬条件**：打开一本多章节 EPUB，只确认并修改第 2 章，导出后第 1、3 章对应文件的字节与原书相同。

## 8. 图片

- 选择器：系统相册或文件；`input` 不设 `capture`，不接入 Camera 插件。
- 插入后立刻压缩：最长边限制（建议 1600px），再压到约 2MB 以内；已小于阈值则不二次损伤。
- 格式：JPEG/PNG/WebP 可读；写入 EPUB 时优先用 JPEG（PNG 带透明则保留 PNG）。
- 编辑器内图片宽度 `100%`，高度自适应，不横向撑破屏幕。
- 无法解码的图：提示插入失败，不写入损坏文件。

## 9. 界面与适配

- 中文文案。
- 手机优先：单栏；章节列表与编辑不要同时挤在一行。电脑上可加宽阅读列，但不做独立桌面信息架构。
- 预留安全区（刘海、Home 条）。
- 编辑时工具栏避开虚拟键盘。
- 触控目标至少约 44px。
- 不依赖悬停才能完成的操作。

主要界面：

1. 书架
2. 章节列表（含书籍菜单）
3. 章节编辑
4. 书籍信息
5. 阅读预览

## 10. 错误处理

全部中文、说明下一步，不抛给用户技术栈关键词（除非个人调试需要写在控制台）。

| 情况 | 行为 |
|---|---|
| 不是 zip / 损坏 | 打不开，书架不新增 |
| 无 OPF / spine 空 | 同上 |
| 加密 EPUB | 「不支持加密的 EPUB」 |
| 存储空间不足 | 自动保存失败提示，保留内存中未写入内容，请用户导出 |
| 导出失败 | 不留下半成品 `.epub` |
| 某章 HTML 转换异常 | 弹窗失败，该章保持 `pristine` |
| 预览原章失败 | 该章只读回退，不影响导出原字节 |

## 11. 技术选型

| 用途 | 选择 |

| 工程 | Vite + React + TypeScript + Capacitor（当前稳定版） |

## 12. 测试与验收

自动化（EPUB 引擎）：

- 最小合法 EPUB 3 可被打开，章节列表正确。
- 新建书导出后，阅读器能识别书名、一章正文、一张图。
- 三章书只简化中间一章：两端章节文件字节不变。
- 加密书被拒绝。
- 增删改排序章节后，OPF spine 与 nav 一致。

手动：

- 手机浏览器能建书、打字、插图、预览。
- Android 真机能打开本地 EPUB、另存为到系统目录、用系统阅读器打开导出文件。
- 横竖屏、键盘弹出时工具栏仍可用。

## 13. 实现顺序

1. Capacitor + Vite + React 空工程，浏览器能打开空白页，Android 工程能同步。
2. 书架 + 应用内存储（先假数据，再接文件系统）。
3. EPUB 引擎：打开、列出章节、导出（先不编辑）。
4. 章节简化转换 + TipTap 编辑 + 自动保存。
5. 插图、压缩、封面与元数据。
6. 章节增删排序、阅读预览、另存为。
7. Android 真机走通打开/导出。

## 14. 风险

- 现有 EPUB 的 HTML 极乱：转换规则必须可测、失败时保持 `pristine`。
- 大书（很多图）在手机内存里解包：导入时流式写入 `original-entries`，避免整本进内存。
- Capacitor 网页回退与 Android 文件选择行为不一致：文件入口集中封装，页面不直接假设路径格式。
